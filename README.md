# TaalimSpace

Приложение: **TaalimSpace**. Команда: **EduSpace**. Хакатон: **AI Academy**.
Каталог преподавателей с бронированием, перепиской и персональным AI-тьютором.
Занятия проходят в Zoom; встроенных видеозвонков нет. MVP для хакатона
AI Academy: React + TypeScript + Tailwind/Vite, FastAPI, PostgreSQL/SQLAlchemy.

## Показ на хакатоне

Локальная страница /presentation переключает два подготовленных учебных аккаунта.
Бронь и сообщения сохраняются в PostgreSQL. Сценарий, подготовка и ограничения:
[docs/PRESENTATION.md](docs/PRESENTATION.md). Этот специальный вход отключить на хостинге.

## Что уже работает

- Адаптивные главная, каталог, профили, кабинеты, чат урока, формы входа.
- Фильтры каталога по предмету, языку, цене, рейтингу и верификации; сортировка.
- Демонстрационный режим без ключей и базы данных, с явной маркировкой данных.
- FastAPI: каталог, регистрация, вход, текущий пользователь, доступ к своим урокам.
- SQLAlchemy-модели и миграции; проверка ролей и принадлежности урока.
- Расчёт комиссии 10% через Decimal; типизированные входы и ответы API.
- Чат с тьютором через Groq: вопросы, контекст урока, последние 10 сообщений и обработка ошибок.
- Чат участников урока и ссылка Zoom; запись загружается вручную в разделе тьютора.
- Учитель публикует услугу и слоты, ученик бронирует без оплаты; отзывы после урока.
- Сдача ДЗ и обратная связь живого учителя, AI-черновик плана следующего занятия.
- Сохранение файла, распознавание Whisper через Groq, конспект, анализ и ДЗ; повтор после ошибки.
- Приватная локальная очередь на диске, восстановление после перезапуска, скачивание исходника и TXT.

## Что пока не подключено

Stripe Checkout реализован только для тестовых ключей и пока не подключён.
PostgreSQL подключён локально; для нового окружения требуется применить миграции.
Серверная запись Zoom не подключается: участник загружает файл вручную.
Email через Brevo/SMTP и Web Push подготовлены, но доставка ещё не подтверждена.
Постоянное облачное хранилище файлов не подключено.
Каталог /catalog и /offers показывают реальные услуги; примеры — /catalog?demo=1.
Инструкция хостинга: [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md).

## Быстрый просмотр frontend

Переписка, Zoom и загрузка записи: [docs/VIDEO_RECORDING.md](docs/VIDEO_RECORDING.md).

Нужны Node.js 22.12+ и pnpm. Из корня проекта:

```sh
pnpm install
pnpm dev
```

Открыть http://127.0.0.1:5173. По умолчанию VITE_DEMO_MODE=true разрешает
демонстрационные кабинеты без входа и примеры из shared/demo-teachers.json.
Реальный каталог, аккаунты и сохранённые данные всегда требуют backend и PostgreSQL.
Для проверки сборки: pnpm build. Установка pnpm фиксируется pnpm-lock.yaml.

## Backend

Нужен Python 3.12+:

```sh
python -m venv .venv
# Windows PowerShell:
.venv\Scripts\Activate.ps1
# macOS/Linux: source .venv/bin/activate
python -m pip install -r requirements-dev.txt
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000 --no-proxy-headers
```

Документация API: http://127.0.0.1:8000/docs.
Health: http://127.0.0.1:8000/api/health. Health показывает готовность процесса
и наличие конфигурации; доступность БД проверяется запросами к ней.
API каталога работает в DEMO_MODE=true без PostgreSQL. Auth и приватные данные
всегда требуют настоящую БД и AUTH_SECRET, даже в демонстрационном режиме API.

## Конфигурация и PostgreSQL

Если .env уже существует, добавляйте отсутствующие параметры из .env.example,
сохраняя ранее внесённый GROQ_API_KEY. Не копируйте файл поверх существующего.

- DATABASE_URL: postgresql+psycopg://USER:PASSWORD@HOST:5432/DATABASE
  (для Supabase используйте параметры подключения своего проекта и SSL).
- AUTH_SECRET: случайная строка длиной не менее 32 символов; генерировать локально.
- CORS_ORIGINS: JSON-массив разрешённых адресов frontend.
- GROQ_API_KEY: серверный ключ для текстового чата с тьютором.
- DEMO_MODE=false: API каталога читает PostgreSQL вместо демонстрационных данных.
- VITE_DEMO_MODE=false: каталог frontend использует данные API вместо демо-профилей. Авторизация доступна в обоих режимах.
- VITE_API_URL=/api: Vite перенаправляет локальные /api на порт 8000.

Для реального режима переключить оба флага DEMO_MODE и VITE_DEMO_MODE в false,
настроить БД/секрет, применить миграцию и перезапустить оба процесса. Новая БД
пустая; демо-профили автоматически в неё не добавляются. Форма услуг и слотов доступна
в кабинете учителя. Короткоживущий токен хранится в памяти, вход после обновления
восстанавливается по HttpOnly-cookie (до 30 дней). Выход отзывает сохранённую сессию;
смена пароля отзывает все сессии и прежние токены доступа.

```sh
python -m alembic upgrade head
# После последующих изменений моделей:
python -m alembic revision --autogenerate -m "describe change"
# Проверьте сгенерированную миграцию перед применением.
```

## Проверки

### Запуск тьютора

Сохраните GROQ_API_KEY в корневом .env, перезапустите backend и откройте
/tutor — отдельный раздел тьютора с загрузкой записи. Для локальной проверки PostgreSQL
не требуется: /api/tutor/demo/chat использует явно обозначенный пример урока.
Ответы настоящие, через официальный Groq SDK (https://github.com/groq/groq-python).
Модель задаётся GROQ_TEXT_MODEL; по умолчанию openai/gpt-oss-120b.
История чата хранится только в памяти страницы; в запросе последние 10 сообщений.
При смене урока/уходе со страницы история сбрасывается. Сохранение в БД — следующий этап.

Демо-API допускает только loopback-клиентов, DEMO_MODE=true и 10 вопросов/минуту
на процесс. Не публикуйте dev-сервер или демо через reverse proxy: перед размещением
отключите оба demo-флага. Live /api/tutor/chat требует JWT и проверяет доступ к уроку;
контекст собирается сервером из его материалов без эталонных ответов ДЗ.
Публичный пилот также требует пользовательских квот и общего ограничения расходов.

После замены ключа перезапустите backend: настройки кэшируются при запуске.
Ошибки ключа, сети и квот отображаются в чате; вопрос остаётся для повторной отправки.

### Команды

```sh
pnpm build
python -m pytest -q
```

Тесты используют временную SQLite в памяти только для проверки логики доступа,
авторизации и ограничений, без сетевых API и рабочих секретов. Для проверки
миграций, JSON-фильтров и конкурирующих транзакций нужна отдельная PostgreSQL.

## Новые функции и проверки

- Фото преподавателя, несколько услуг с разными ценами, скрытие услуг.
- Редактирование и удаление свободных слотов; отмена и перенос до начала занятия.
- Контроль пересечений обучения и преподавания одного пользователя.
- Отдельные личные диалоги до бронирования, избранные преподаватели, тексты отзывов.
- PNG/JPEG/WebP/PDF/TXT в чате урока; приватное скачивание участниками.
- Создание и редактирование ДЗ учителем, срок сдачи, ручная проверка.
- Напоминания в кабинете; email и push включаются отдельно после настройки.
- Отчёт по урокам/темам/сданным работам, личные заметки и карточки для повторения.
- Восстановление пароля по одноразовой ссылке. Настройка: [EMAIL_SETUP.md](docs/EMAIL_SETUP.md).

Проверено 25 серверных тестов. Отдельная проверка реального PostgreSQL:
`python -m scripts.check_postgres` — создаёт случайную временную схему, проверяет
две конкурирующие брони и удаляет только созданную тестовую схему. Рабочие таблицы
не меняет. Запускать явно, с настроенным DATABASE_URL.

Актуальные ограничения и непроверенные интеграции: [MVP_AUDIT.md](docs/MVP_AUDIT.md).

## Единый аккаунт

Регистрация: имя, email и пароль, без выбора роли. Каждый аккаунт может учиться. Раздел «Стать преподавателем» позволяет заполнить и опубликовать профиль через POST /api/offers/mine, затем добавить слоты. Это включает преподавание и сохраняет все возможности ученика. Кабинеты «Учусь / Преподаю» фильтруют уроки и ДЗ по участию; проверки и завершение доступны только преподавателю конкретного занятия. Поле role=teacher обозначает дополнительную возможность преподавать, а не запрет учиться.
