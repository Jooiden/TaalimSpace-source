# Презентация TaalimSpace на хакатоне

Проверка подготовки: 26 серверных тестов и сборка прошли. В браузере выполнены
бронь учебного слота и отправка сообщений от обеих ролей. Учебный TXT загружен
в прошлый урок; Groq вернул и сохранил конспект, анализ, ДЗ и дополнительную практику.
Это проверка анализа текста, не проверка распознавания реальной аудиозаписи.

Открыть http://127.0.0.1:5173/presentation. Подготовленные аккаунты имеют имена
«Демо · Алексей, ученик» и «Демо · Анна, преподаватель». Все действия сохраняются
обычными endpoints в PostgreSQL, это не имитация успешного бронирования/чата.
Не вводить реальные персональные данные в общедоступные учебные аккаунты.

## Подготовка на локальном компьютере

1. Запустить `python -m alembic upgrade head`.
2. Запустить `python -m scripts.prepare_presentation` из корня проекта.
   Скрипт добавляет только учебные аккаунты, две услуги, свободные слоты на четыре
   дня, прошлый урок и одно ДЗ. Повтор не очищает сообщения/брони и не сбрасывает
   уроки; добавляет недостающие будущие слоты. Случайные пароли не публикуются.
3. Перезапустить backend. Нужны DEMO_MODE=true и локальный адрес 127.0.0.1.
4. Открыть /presentation. Вход работает только для двух заранее заданных ID,
   с проверкой локального клиента, адреса сервера и Origin. Нормальные аккаунты
   через этот вход недоступны. Перед публичным размещением обязательно
   PRESENTATION_ENABLED=false и DEMO_MODE=false. Не публиковать локальный сервер
   презентации через туннель/reverse proxy.

## Показ на 5–7 минут

1. «Войти как ученик» → каталог → Демо · Анна → выбрать время → записаться.
2. Кабинет ученика → новый урок → чат → отправить вопрос и прикрепить файл.
3. «Презентация» в верхней полосе → войти как преподаватель → тот же урок →
   прочитать вопрос и ответить; добавить свою настоящую Zoom-ссылку.
4. Показать услуги/разные цены и редактирование свободного времени. Перенос и
   отмену демонстрировать на будущей брони, не на прошлом учебном уроке.
5. Тьютор → прошлый урок → загрузить собственную запись с согласия участников.
   Быстрый вариант: скачать /presentation-lesson.txt и загрузить как текст.
   Этот вариант показывает реальный анализ Groq, но НЕ транскрипцию аудио.
   Для распознавания речи есть /presentation-audio.wav — вымышленный урок,
   озвученный искусственным голосом. Его транскрипция и анализ проверены через Groq.
6. Задать тьютору вопрос по результату. Показать конспект, темы и отдельно
   задания учителя/дополнительную практику ИИ.
7. Ученик сдаёт подготовленное ДЗ → преподаватель проверяет → ученик видит
   комментарий и может оставить отзыв после завершённого урока.

Одновременно две роли: использовать разные браузеры или обычное + приватное
окно. В одном браузере cookie общие между вкладками; две вкладки не изолируют
аккаунты. Для последовательного показа достаточно кнопок смены роли.

## Дополнительные функции

- Сохранение входа: обновить страницу после входа.
- Фото и несколько услуг: кабинет преподавателя.
- Переписка до бронирования: «Написать» в каталоге; после — чат урока.
- Файлы/картинки: чат урока, только участникам.
- Создание ДЗ: карточка занятия в кабинете учителя.
- Напоминания: /notifications; задания со сроком появляются в кабинете.
- Избранное, прогресс, библиотека заметок/карточек.

## Что не выдавать за подключённое

Zoom — внешний сервис, запись вручную. Email/Brevo и Push требуют настройки
и проверки доставки; для письма использовать свой реальный аккаунт, а не
адрес example.com учебного пользователя. Stripe пока не подключён, деньги
не списываются. Автоматических выплат учителю нет. Заранее подготовленный
урок и задание подписаны как учебный пример; его не нужно выдавать за реальную
историю ученика. Для AI необходимы интернет, Groq API и доступная квота.
