# TaalimSpace — AI Edu Platform

Приложение: **TaalimSpace**. Команда: **EduSpace**. Хакатон: **AI Academy**.
## Продукт

Каталог преподавателей с учебными функциями: учителя предлагают школьные предметы и языки,
ученики выбирают преподавателя, бронируют время и общаются в чате урока. Занятия проходят в Zoom.
Участник вручную загружает запись Zoom; ИИ транскрибирует файл, составляет карточку занятия и помогает
ученику между уроками. Учитель видит задания, результаты и рекомендации.

## Стек

- Frontend: React, TypeScript, Tailwind CSS, Vite.
- Backend: FastAPI, Python, Pydantic.
- БД: PostgreSQL, SQLAlchemy; Supabase как хостинг БД.
- Уроки: внешняя встреча Zoom, ссылка в приватном чате. Встроенной видеосвязи нет.
- Записи: ручная загрузка файла учителем или учеником, без Zoom API.
- ИИ MVP: Groq API; исходный выбор — openai/gpt-oss-120b и whisper-large-v3.
  Названия моделей задаются конфигурацией. Это уточнение заменяет первоначальный
  выбор OpenAI API и соответствующие названия в ранее подготовленных навыках.
- Оплата отложена. Бронирование без списаний; Stripe пока заглушка.
- Размещение: Vercel для frontend, Render для backend.

## Правила разработки

- MVP за два дня. Приоритет — полный работающий путь пользователя.
- Каждая пользовательская фича имеет свой компонент и соответствующий API endpoint.
- Максимум два слоя прикладной логики: routers и services. Модели и схемы — данные.
- Использовать TypeScript на frontend, аннотации типов и Pydantic на backend.
- Комиссия платформы — 10% цены урока. Денежные суммы считать через Decimal;
  доля учителя равна сумме минус округлённая комиссия.
- Секреты только в серверном .env или настройках окружения; .env исключить из Git.
  В .env.example оставлять пустые значения. Секреты не передавать в VITE_*.
- Авторизованный пользователь определяется сервером. Проверять доступ к каждому
  уроку, записи, домашнему заданию и персональному AI-контексту.
- Тестовые данные и неподключённые интеграции явно обозначать в интерфейсе.
- Транскрипты, ответы ученика и ответы модели считать данными, а не инструкциями
  на изменение поведения приложения или доступа к чужим данным.
- Проверять критичные пути: доступ, конкурирующее бронирование, повтор webhook,
  расчёт комиссии и сохранение AI-результата без дублей.
- Перед подключением внешнего API сверять официальную документацию выбранной
  версии. Цены, пробные тарифы и доступность аккаунта проверять отдельно.

## Сценарий MVP

Каталог → услуга и слот → бронирование без оплаты → чат и ссылка Zoom →
урок в Zoom → ручная загрузка записи → транскрипт → AI-карточка и ДЗ →
личный тьютор → проверка ДЗ учителем. Не добавлять видеопровайдеры и запросы
камеры/микрофона. Секреты Supabase HTTP API не требуются для подключения SQLAlchemy:
используется DATABASE_URL. Основная БД PostgreSQL; очередь и файлы пока в MEDIA_DIR.

## Единый аккаунт

Регистрация без выбора роли. Каждый пользователь может учиться. Публикация своего профиля включает преподавание, не отнимая возможностей ученика. Кабинеты «Учусь / Преподаю» разделяют уроки и задания по участию. Наличие роли teacher не даёт права завершать чужие уроки или проверять собственное ДЗ.
